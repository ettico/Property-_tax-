# ביקורת ארנונה — אשד מול עיריית ירושלים

מערכת שמצליבה, אחת לחודש, בין מה שחברת אשד הזינה למערכת הארנונה של עיריית
ירושלים (קובץ אקסל חודשי) לבין מסמכי הסקר בשטח (טפסי מדידה סרוקים), ומאמתת
ששני דברים נכונים: שהשטח שהוזן תואם את מה שנמדד בפועל, ושהעמלה שאשד קיבלה
מחושבת נכון לפי החוזה הרלוונטי (מזרח ירושלים / מערב ירושלים — לכל אחד חוזה
ותעריפים נפרדים).

זה **לא** מערכת גבייה וזה לא מזין נתונים לשום מקום — היא רק מבקרת בדיעבד
ומפיקה דוח חריגות.

## מצב נוכחי

מנוע החישוב הליבתי בנוי ובדוק (`src/lib`), על בסיס שני החוזים החתומים
(מכרז 159.2022 למזרח, מכרז 80.2021 למערב) ואומת מול שורות אמיתיות מייבוא
חודשי מאושר:

- `types.ts` — הטיפוסים המשותפים (צד, סוג פעולה, שיטת חישוב).
- `rules.seed.ts` — הכללים בפועל מהחוזים, כנתונים (לא קוד קשיח) כדי
  שעדכון תעריף/הצמדה יהיה שינוי דאטה ולא שינוי קוד. שדה `unverified` מסמן
  כלל ששוחזר אמפירית ולא אומת מול נוסח החוזה (התעריף הקבוע ל"איתור
  מחזיקים" במערב, 258 ש"ח).
- `commissionEngine.ts` — מחשב את העמלה הצפויה לפי צד+סוג פעולה+תאריך,
  ומשווה למה שבפועל שולם.
- `splitCheck.ts` — מזהה פיצול (נכס אב שמפסיד שטח + נכס בן חדש שמקבל אותו
  שטח, באותו תאריך) ומסמן חוסר איזון.
- `excelParser.ts` — קורא את קובץ ה-"אקסל" החודשי, שבפועל הוא טבלת HTML
  שנשמרה בסיומת .xls (ייצוא Telerik grid), לא קובץ בינארי.
- `auditPipeline.ts` — מריץ את כל הבדיקות על שורות חודש שלם ומפיק רשימת
  חריגות (`Finding[]`).
- `documentExtraction.ts` — קורא דף אחד סרוק מתיק הסקר ומחזיר JSON מבני
  (סוג מסמך, גוש/חלקה/תת, שטח נטו, קובעי מס, "נכס חדש") **באמצעות מודל
  Claude עם ראייה, לא OCR קלאסי** — הדפים ברובם כתב יד עברי, ש-OCR (למשל
  Tesseract, שנוסה בפועל על החוזים בפרויקט הזה) קורא בצורה לא אמינה,
  לעומת מודל ראייה שקורא אותם נכון. שדה כלשהו שלא קריא בבירור מוחזר כ-
  `null` ומצוין ב-`uncertainFields` — המודל לא מנחש בשקט. בררת המחדל היא
  המודל החזק ביותר (`claude-opus-5`, קבוע `EXTRACTION_MODELS.accurate`)
  כי כתב יד + השלכות כספיות = טעות קריאה יקרה; ניתן להחליף למודל מהיר/זול
  יותר (`balanced`/`fast`) דרך משתנה הסביבה `EXTRACTION_MODEL_ID`, בלי
  לגעת בקוד.

`prisma/schema.prisma` מגדיר את מודל הנתונים המלא (כללי עמלה, טבלת
אזורים/תעריפים מצו המיסים, ייבוא חודשי, מסמכי סקר, חריגות) — עדיין לא
מחובר ל-DB בפועל.

## מה עוד חסור

- אימות סעיף העמלה הקבועה ל"איתור מחזיקים" (258 ₪) מול נוסח חוזה בפועל.
- טעינת טבלת האזורים המלאה (נספח ד' לצו המיסים) כדי לפתור צד (מזרח/מערב)
  אוטומטית לפי גוש-חלקה, ולא רק דרך פונקציית `resolveSide` שמוזרקת מבחוץ.
- חיבור `documentExtraction.ts` בפועל לקובצי PDF (המרת עמוד ל-base64
  ושליחה), והתאמת הפלט שלו לשורת האקסל הנכונה לפי גוש-חלקה-תת מדויק.
- מסכי UI: העלאה חודשית, דוח חריגות, מסך נכס בודד.
- חיבור בסיס הנתונים (Postgres/Prisma) ואחסון קבצים (S3), בהמשך למוסכם.
